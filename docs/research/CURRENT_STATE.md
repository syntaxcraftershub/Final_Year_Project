## 2. What is incomplete or missing entirely

- **No `database/` directory exists in the repo or the clone.** `.gitignore` deliberately excludes `database/raw/` and `database/processed/` because `golden_4_ApiKeyLeak.jsonl` contains synthetic-but-format-valid fake credentials (`ghp_`, `AKIA`, etc.) that trip GitHub push protection. The raw TraceSafe data must be downloaded fresh from `github.com/yenshan0530/TraceSafe` (mirrors `CyCraftAI/TraceSafe` on HF) before anything can run. Confirmed reachable via `git clone` (HTTPS) in this environment; the GitHub API (`api.github.com`) is *not* reachable in this session's network allowlist, so raw `git clone` is the working path, not the API.
- **No `source/tiers/` package, no `source/cascade.py`, no `source/splits.py`, no `source/metrics.py`.** None of these exist yet — Phase 4 onward is greenfield relative to `main`.
- **No benign twins parsed.** Current parser only reads `new_trace`; `original_trace` (the unmutated twin inside every malicious record) is never extracted. This is why the corpus is 90 benign / 1,080 malicious — a 12:1 imbalance the design doc flags as making FPR non-credible.
- **No calibration/test split exists.** All historical experiments (`phase2_sanity_check.py`, `phase3_drift_plots.py`) sampled directly from the full corpus with `random.seed(...)`, which is fine for exploratory/illustrative work but is explicitly *not* a calibration/test discipline — there is no notion of a held-out set anywhere in `main`.
- **No NLI tier, no local-LLM tier.** `env/requirements.txt` has no `torch`, `transformers`, `protobuf`, or `sentencepiece` — none of the packages Tier 1/Tier 2 need are installed or declared yet.
- **No threshold calibration file, no `result/e*.py` experiment scripts, no `result/run_all.py`.**
- **`connectors/llm_gate.py` (Ollama/NIM) is dead code from the product's perspective** — never imported by `pipeline.py` or `backend/server.py`. It remains valid as an *optional alternative* Tier 2 backend per the design spec (§4.6), but the default research path must use local HF transformers instead, specifically to keep the critical path offline and reproducible (cloud API in the critical path is a non-goal per the design's constraints).
- **No `docs/research/` documentation** beyond this new file — `research_questions.md`, `methodology.md`, `experiment_protocol.md`, `reproducibility.md`, `limitations.md`, `results_interpretation.md` all need to be created (Phase 12/14 of the mission brief).
- **No `papers/` directory** — conference/journal manuscripts, `references.bib`, `references_verified.md` do not exist.
- **No git branch for this work** — `main` only has two commits (initial commit + implementation-plan doc commit). Per instructions this work must happen on `research/cascade-completion`, not directly on `main`.

## 4. Current hypotheses and their status

| Hypothesis | Status | Evidence |
|---|---|---|
| H1: Whole-trajectory embedding distance (intent vs. full trace) separates benign from malicious | **Weak/inconclusive** | `result/phase2_sanity_check.py`: malicious mean 0.59–0.64 vs benign 0.57, heavy overlap, n=10 per group (too small to be conclusive either way). |
| H2: Cumulative drift (distance to intent after each prefix) climbs for malicious, stays flat for benign | **FAILED — see §3 negative finding below** | `result/phase3_drift_plots.py` aggregate check, 60 benign vs 60 drift-category-malicious (≥3 steps): ROC-AUC 0.47–0.57 across `final/mean/max/slope_all/slope_last3/rise`. 0.50 = chance. Diagnosed causes (design spec §1): (a) growing prefix text dilutes early divergence, (b) sentence embeddings capture topic similarity not goal alignment, (c) TraceSafe mutations are often single-tool-call swaps, small in embedding space. |
| H3: Step-to-step delta (distance between consecutive step vectors) spikes at the pivot point | **Promising on one worked example, NOT yet validated dataset-wide** | README §7 shows a single trajectory (`3_UserInfoLeak_0`) where delta jumps from 0.29→0.76 exactly at the malicious pivot (`authenticate_twitter`). This is explicitly flagged in both the README and the design spec as an illustrative anecdote, not a result — it is the reason Experiment E1 (Tier 0 feature ROC-AUC across the *whole* calibration split) is the first evaluation gate for the new work. |
| H4 (new, from the design spec): NLI entailment (does the action follow from the task?) will outperform embedding distance because it measures goal alignment rather than topic similarity | **Untested — this is what E2 exists to check** | Not yet implemented in `main`. |
| H5 (central research question): a tiered cascade can approximate always-on LLM-judge detection quality at substantially lower average cost | **Untested — the entire point of Phases 4–10 below** | No cascade code exists yet. |

## 5. Known negative findings (must remain visible per the honesty guardrails)

1. **Cumulative embedding drift does not separate benign from malicious trajectories.** ROC-AUC 0.47–0.57, i.e., statistically indistinguishable from a coin flip on the tested slice. This is reported plainly in the current README and must **not** be quietly dropped or re-labeled as a positive result in any later document this project produces.
2. **A false-positive rate computed from 90 benign records is not credible** (design spec §3.1) — this is the stated motivation for benign-twin extraction, and it means every historical number that used the raw 90-benign sample (including the Phase 2/3 scripts above) carries this caveat and should not be quoted as a final result.
3. **TraceSafe's "malicious" label blends two qualitatively different failure types**: genuine intent-divergence attacks (`PROMPT_INJECTION`, `PRIVACY_LEAKAGE`) and operational defects (`HALLUCINATION`, `INTERFACE_INCONSISTENCIES` — e.g. `HallucinatedTool`, `VersionConflict`, `MissingTypeHint`). A blended overall number risks misrepresenting what the monitor actually detects; per-category reporting is mandatory going forward (design spec §3.5, mission brief Phase 9).

## 6. Planned research contribution (unchanged from the approved spec)

Central research question: *can a cheap tiered monitoring cascade (embeddings → NLI → local LLM) detect trajectory-level agent divergence while substantially reducing expensive LLM inference compared with always-on LLM judging?*

Three-tier cascade, cheapest first, each tier abstains rather than guesses:
- **Tier 0** — embedding features (max step-to-step delta as decision signal; cumulative drift retained only for reporting, given its known failure).
- **Tier 1** — NLI cross-encoder (`cross-encoder/nli-deberta-v3-base`), measuring goal alignment (entailment) rather than topic similarity, specifically to repair diagnosed cause H2(b).
- **Tier 2** — local HF LLM judge (`Qwen/Qwen2.5-1.5B-Instruct`, CPU), terminal, always decides.

Evaluated with: benign-twin matched-pair design, leakage-safe pair-grouped 40/60 calibration/test split, frozen-before-test-run thresholds, per-category and per-length reporting, and a paired score (attack caught AND its twin cleared) as the strictest headline metric.

## 8. Conclusion

The repository matches its own README's self-assessment: Phases 0–2 (data, embeddings, streaming demo) are genuinely done; the original cumulative-drift hypothesis is genuinely falsified; step-to-step delta is a genuine but unvalidated lead. Nothing about the cascade, splitting, calibration, or metrics infrastructure exists yet on `main`. The approved design spec and implementation plan (`docs/superpowers/specs/2026-07-21-shadowtrace-cascade-design.md`, `docs/superpowers/plans/2026-07-21-shadowtrace-cascade.md`) already contain fully worked-out code for Tasks 1–16, which this audit treats as the specification to implement faithfully — not to redesign. Implementation begins at Phase 2 (benign twins) next, on a new `research/cascade-completion` branch.
